# LCS：動態規劃（DP） vs 非動態規劃（暴力枚舉）

> 此專案由opencode說明與範例製作，目的是用 LCS 說明動態規劃與非動態規劃的差異。

## 一、問題說明

本次以 **最長共同子序列（Longest Common Subsequence, LCS）** 為例，分別使用「動態規劃」與「非動態規劃（暴力枚舉所有子序列）」兩種方式來解決此文字類型問題。

- **子序列（Subsequence）**：從字串中刪除部分（或全部）字元後，保留剩餘字元原有順序所組成的新字串。不要求字元必須連續。
- **共同子序列（Common Subsequence）**：同時為兩個字串的子序列。
- **最長共同子序列（LCS）**：在所有共同子序列中，長度最大的那一個（可有多個同長度）。

**範例：**

```text
A = "AGGTAB"
B = "GXTXAYB"
LCS = "GTAB"，長度為 4
```

此問題與 **diff（檔案差異比對）** 的核心概念息息相關，因此非常適合用來說明 DP 相較於暴力解法的差異。

## 三、動態規劃（DP）解法

### 3.1 原理

LCS 同時滿足：

- **最優子結構（Optimal Substructure）**：兩字串的 LCS，可以由其前綴的 LCS 推導而得。
- **重疊子問題（Overlapping Subproblems）**：在遞推過程中，會重複計算相同的 `(i,j)` 前綴狀態。

定義 $dp[i][j]$ 為字串 $A[0..i-1]$ 與 $B[0..j-1]$ 的 LCS 長度，遞迴關係如下：

$$
dp[i][j]=\begin{cases}
0, & i==0 \lor j==0\\
dp[i-1][j-1]+1, & A[i-1]==B[j-1]\\
\max(dp[i-1][j], dp[i][j-1]), & A[i-1]!=B[j-1]
\end{cases}
$$

- **字元相等**：將此字元納入 LCS，因此長度為 $dp[i-1][j-1]+1$
- **字元不相等**：至少捨棄 $A$ 的最後一個或 $B$ 的最後一個字元，取兩者較大值

### 3.2 複雜度

- **時間複雜度**：$O(mn)$，其中 $m=|A|, n=|B|$
- **空間複雜度**：$O(mn)$（完整二維表）。若僅需最終長度，也可使用滾動陣列將空間壓至 $O(\min(m,n))$
- **正確性**：精確解

### 3.3 執行方式

```bash
cd 07
python lcs_dp.py
```

## 四、非動態規劃（暴力枚舉子序列）解法

### 4.1 原理

1. 選擇兩個字串中較短的 $S$ 作為枚舉對象，較長的 $T$ 用於驗證（降低枚舉量）。
2. 使用 **回溯（Backtrack）** 產生 $S$ 的所有子序列：對每個字元採取「取」或「不取」兩種選擇。
3. 對每個產生的子序列 $s$，以 **雙指針** 判斷 $s$ 是否為 $T$ 的子序列。
4. 追蹤所有合法子序列中，長度最大的值即為答案。

此做法完全沒有記憶化，也不重用已計算過的中間狀態。

### 4.2 複雜度

- **時間複雜度**：$O(\max(m,n) \cdot 2^{\min(m,n)})$
- **空間複雜度**：$O(\min(m,n))$（遞迴深度與當前序列）
- **正確性**：精確解（窮舉所有子序列必定包含真實的 LCS）

### 4.3 執行方式

```bash
cd 07
python lcs_brute.py
```

> **注意：** 若 $\min(m,n) > 20$，暴力法幾乎無法在實際時間內完成，僅供教學觀念使用。

## 五、兩者比較

| 比較面向 | **動態規劃（DP）** | **非動態規劃（暴力枚舉子序列）** |
|---|---|---|
| **解題思路** | 最優子結構 + 重疊子問題，透過 dp 表快取結果 | 窮舉所有子序列，再逐一檢查 |
| **時間複雜度** | $O(mn)$（多項式） | $O(\max(m,n)\cdot 2^{\min(m,n)})$（指數） |
| **空間複雜度** | $O(mn)$（可優化至 $O(\min(m,n))$） | $O(\min(m,n))$ |
| **是否利用重疊子問題** | 是 | 否 |
| **正確性** | 精確 | 精確 |
| **實用性** | 高（diff、版本比對等） | 極低（僅教學用） |
| **可擴展性** | 適合中等長度字串 | 僅適合極短字串 |

## 六、結論

- **暴力枚舉**：思路直覺，但複雜度呈指數成長。
- **動態規劃**：藉由「重疊子問題只算一次」與「空間換時間」，將指數降為多項式 $O(mn)$。

對 LCS 而言，**動態規劃才是實際可行的解法。**
