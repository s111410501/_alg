## 1. 老鼠走迷宮問題（DFS）

### 問題描述

給定一個二維迷宮，`#` 代表牆壁、`.` 代表通道、`S` 代表老鼠起點、`E` 代表出口。老鼠每次只能往上、下、左、右移動一格，不能穿牆，也不能重複走過同一個格子。目標是找到一條從 `S` 到 `E` 的路徑。

本程式使用 **DFS（Depth-First Search，深度優先搜尋）**，並搭配 **回溯（backtracking）** 與 `visited` 集合避免重複拜訪。

### 搜尋法設計

- **狀態表示**：目前所在的格子座標 `(x, y)`。
- **起始狀態**：迷宮中的 `S`。
- **目標測試**：目前格子是否為 `E`。
- **狀態轉移**：往上、下、左、右移動一格。
- **合法條件**：
  - 新格子必須在迷宮範圍內。
  - 新格子不能是牆壁 `#`。
  - 新格子不能已經拜訪過。
- **路徑重建**：使用 `parent` 字典記錄每個格子的前一個格子，找到出口後從 `E` 往回追到 `S`，再反轉成正確順序。

### DFS 的特性

DFS 會沿著一條路一直往深處走，直到碰到死路才回溯。這種策略實作簡單、記憶體需求相對較低，但不保證找到最短路徑。以本程式的迷宮為例，DFS 找到的路徑長度為 21 格、移動 20 步，但這不一定是全迷宮中最短的路徑。

### 複雜度

- 時間複雜度：`O(V + E)`，其中 `V` 是可走格子數、`E` 是相鄰通道數。
- 空間複雜度：`O(V)`，主要用於遞迴堆疊、`visited` 與 `parent`。

### 執行方式

```bash
python 01_maze_dfs.py
```

程式會印出原始迷宮、DFS 找到的路徑（以 `*` 標示）、路徑長度、移動步數、探索格子數、移動順序與路徑座標。

## 2. 狼羊甘藍菜過河問題（BFS）

### 問題描述

農夫要帶著狼、羊、甘藍菜一起過河。河上只有一艘小船，農夫每次只能帶 **一樣東西** 過河，也可以獨自過河。當農夫不在同一岸時：

- 狼不能和羊單獨在一起。
- 羊不能和甘藍菜單獨在一起。

目標是讓農夫、狼、羊、甘藍菜全部安全到達對岸，並求出 **最少過河次數**。

本程式使用 **BFS（Breadth-First Search，廣度優先搜尋）**。

### 狀態表示

使用四元組：

```text
(farmer, wolf, goat, cabbage)
```

每個元素代表該角色目前在哪一岸：

- `0`：起始岸
- `1`：對岸

因此起始狀態是 `(0, 0, 0, 0)`，目標狀態是 `(1, 1, 1, 1)`。

### 合法狀態判斷

對每一岸檢查：如果農夫不在該岸，則該岸不能同時出現「狼和羊」，也不能同時出現「羊和甘藍菜」。只要有任何一岸違反規則，該狀態就是非法狀態。

### 狀態轉移

農夫過河時可以：

1. 獨自過河。
2. 帶走與農夫同岸的狼。
3. 帶走與農夫同岸的羊。
4. 帶走與農夫同岸的甘藍菜。

每次轉移後，農夫與被帶走的物品所在岸都會翻轉，接著檢查新狀態是否合法。

### BFS 的特性

BFS 會一層一層地擴展狀態，因此第一次抵達目標狀態時，一定是在 **最少過河次數** 下抵達。本題總狀態數最多只有 `2^4 = 16` 種，搜尋空間非常小，程式實際只探索 10 個狀態就找到答案。

解答共需要 **7 次過河**：

```text
農夫帶羊過河
農夫獨自回來
農夫帶狼過河
農夫帶羊回來
農夫帶甘藍菜過河
農夫獨自回來
農夫帶羊過河
```

### 複雜度

- 狀態數：`2^4 = 16`。
- 時間複雜度：`O(V + E)`，其中 `V` 是合法狀態數、`E` 是合法轉移數。
- 空間複雜度：`O(V)`，用於佇列、`parent` 與 `visited`。

### 執行方式

```bash
python 02_river_crossing_bfs.py
```

程式會逐步列出每一次過河動作、過河後的兩岸狀態、總過河次數與完整狀態序列。

## 3. 八皇后問題（DFS）

### 問題描述

在 `8 x 8` 的棋盤上放置 8 個皇后，使任兩個皇后都不會互相攻擊。皇后可以攻擊同一列、同一行與同一條斜線上的棋子，因此每個皇后必須滿足：

- 不同一列。
- 不同一行。
- 不同一條左上到右下的斜線。
- 不同一條右上到左下的斜線。

本程式使用 **DFS + 回溯法（backtracking）**，並可推廣到 `N` 皇后問題。

### 搜尋法設計

程式採 **逐列放置** 的方式：

- 從第 0 列開始，依序在每一列放一個皇后。
- 對每一列嘗試所有行 `0 ~ N-1`。
- 使用三個集合快速檢查衝突：
  - `columns`：已使用的行。
  - `diagonal_down`：已使用的 `row + column` 斜線。
  - `diagonal_up`：已使用的 `row - column` 斜線。
- 如果某個位置不衝突，就暫時放置皇后，遞迴處理下一列。
- 如果下一列找不到合法位置，就回溯：移除剛剛放置的皇后，換下一個行。
- 當 `row == N` 時，代表找到一個完整解答。

### DFS 的特性

八皇后問題的搜尋樹非常龐大，但透過「同一行、同一斜線」的即時檢查，可以在很早的階段剪掉大量不可能的分支。DFS 搭配回溯非常適合這類 **限制滿足問題（Constraint Satisfaction Problem, CSP）**。

本程式預設會找出 8 皇后的所有解答，8 皇后共有 **92 組解**，並印出第一個解答。

### 複雜度

- 最壞時間複雜度：`O(N!)`，但實際上會因為斜線與行衝突檢查而大幅剪枝。
- 空間複雜度：`O(N)`，用於遞迴深度、三個集合與目前擺放方式。

### 執行方式

```bash
python 03_eight_queens_dfs.py
python 03_eight_queens_dfs.py 8
python 03_eight_queens_dfs.py 8 --first
python 03_eight_queens_dfs.py 6
```

- 第一個參數 `N` 代表皇后數量，預設為 8。
- 加上 `--first` 表示找到第一個解就停止，不再搜尋所有解。

程式會印出棋盤、皇后位置（列與行皆從 1 開始）、解答數量與探索的遞迴節點數。

## 4. NPC 搜尋玩家問題（A*）

### 問題描述

在一個二維網格地圖中，`N` 代表 NPC、`P` 代表玩家、`#` 代表障礙物、`.` 代表平地、`~` 代表沼澤。NPC 每次可以往上、下、左、右移動一格，目標是找到一條從 NPC 到玩家的路徑。

不同地形有不同的移動成本：

- 平地 `.`：成本 1。
- 沼澤 `~`：成本 3。
- 起點 `N` 與玩家 `P`：成本 1。

本程式使用 **A*（A Star）啟發式搜尋**，目標不只是找到路徑，而是找到 **總移動成本最低** 的路徑。

### A* 的評估函數

A* 對每個節點 `n` 計算：

```text
f(n) = g(n) + h(n)
```

- `g(n)`：從起點走到 `n` 的實際累積成本。
- `h(n)`：從 `n` 到目標的預估成本，本程式使用 **曼哈頓距離**：

```text
h(n) = |x_n - x_goal| + |y_n - y_goal|
```

因為每一步的最低成本是 1，曼哈頓距離不會高估實際成本，所以這個啟發函數是 **可採納的（admissible）**，也是 **一致的（consistent）**。因此 A* 可以保證找到最低成本路徑。

### 搜尋法設計

- 使用 **最小堆積（min-heap / priority queue）** 儲存待展開節點，優先展開 `f(n)` 最小的節點。
- 使用 `g_score` 記錄目前已知到每個格子的最低成本。
- 使用 `parent` 記錄路徑來源。
- 使用 `closed` 集合避免重複展開已處理的節點。
- 找到目標後，從 `P` 沿著 `parent` 回推，重建完整路徑。

### A* 的特性

A* 結合了 Dijkstra 的「實際成本」與 Greedy Best-First Search 的「往目標方向前進」特性。當啟發函數良好時，A* 通常能比 Dijkstra 展開更少的節點，同時仍保證最佳解。本程式中，A* 找到的路徑總成本為 30，共展開 30 個節點。

### 複雜度

- 時間複雜度：最壞為 `O(E log V)`，其中 `V` 是格子數、`E` 是相鄰邊數；實際表現取決於啟發函數品質。
- 空間複雜度：`O(V)`，用於 `g_score`、`parent`、`closed` 與優先佇列。

### 執行方式

```bash
python 04_npc_astar.py
```

程式會印出地圖、A* 找到的路徑（以 `*` 標示）、路徑長度、移動步數、總成本、展開節點數與路徑座標。

## 5. IC 設計中的電路繞線問題（多種方法）

### 問題描述

在 IC 設計中，晶片上有多個需要連接的端子（net），繞線器必須在有限的晶片面積中，避開障礙物，為每一條 net 找到連接路徑。這個問題本質上是一種 **網格圖上的路徑搜尋問題**，也可以視為多條連線的尋路與資源分配問題。

本程式在一個 `20 x 12` 的網格上模擬繞線：

- `#`：障礙物，不可通過。
- `~`：壅塞區，通過成本為 3。
- `.`：一般區域，通過成本為 1。
- 每條 net 以一個英文字母表示（A、B、C）。

程式依序為每條 net 繞線；一旦某條 net 完成，它的路徑會被視為障礙物，後面的 net 不能再重疊使用，以模擬 **單層繞線（single-layer routing）** 的資源限制。

### 使用的四種方法

本程式實作並比較以下四種搜尋方法：

| 方法 | 資料結構 | 策略 | 特點 |
|---|---|---|---|
| **BFS / Lee 演算法** | 佇列（queue） | 一層一層擴展 | 保證最少格子數，但不考慮地形成本 |
| **DFS** | 堆疊（stack） | 一直往深處走 | 實作簡單，但不保證最短路徑，可能繞很遠 |
| **Dijkstra** | 優先佇列（min-heap） | 每次展開目前成本最低的節點 | 保證最低總成本，適合加權圖 |
| **A*** | 優先佇列（min-heap） | `f = g + h`，`h` 為曼哈頓距離 | 保證最低成本，通常展開節點數比 Dijkstra 少 |

### 繞線流程

1. 建立初始障礙物集合 `blocked`。
2. 依 `NETS` 的順序，對每條 net 執行指定的搜尋演算法。
3. 若找到路徑：
   - 累計線長與成本。
   - 將路徑上的所有格子加入 `blocked`，避免後續 net 重疊。
4. 若找不到路徑，記錄該 net 繞線失敗。
5. 對 BFS、DFS、Dijkstra、A* 各執行一次完整流程，最後比較成功率、總線長、總成本、展開節點數與執行時間。

### 本程式的比較結果

以下為程式實際執行後的典型結果（執行時間會因電腦而異）：

| 演算法 | 成功數 | 總線長 | 總成本 | 展開節點數 |
|---|---:|---:|---:|---:|
| BFS | 3 / 3 | 66 | 76 | 339 |
| DFS | 1 / 3 | 69 | 73 | 149 |
| Dijkstra | 3 / 3 | 68 | 74 | 398 |
| A* | 3 / 3 | 66 | 74 | 193 |

結果分析：

- **BFS** 找到的總線長最短（66），但它只看格子數，不看壅塞成本，因此總成本較高（76）。
- **DFS** 雖然很快找到第一條路徑，但路徑可能又長又曲折，會佔用大量格子，導致後面的 net 無法繞線，所以只成功 1 條。
- **Dijkstra** 能找到最低總成本（74），但因為沒有方向性啟發，展開的節點數最多（398）。
- **A*** 同樣找到最低總成本（74），且因為使用曼哈頓距離啟發函數，只展開 193 個節點，效率比 Dijkstra 好。

### 為什麼 DFS 不適合多條 net 的繞線？

DFS 只保證「找到一條可行路徑」，不保證路徑最短，也不考慮成本。它可能先佔用一大片區域，讓後面的 net 被擋住。這說明了在 IC 繞線中，單靠 DFS 通常不夠，必須搭配成本函數、順序優化，甚至 **rip-up and reroute（拆線重繞）**。

### 實務上的延伸

真實的 IC 繞線問題比本範例複雜得多，通常還會考慮：

- 多層金屬層（multi-layer routing）與貫孔（via）成本。
- 轉彎成本（bend penalty）。
- 線寬、間距與設計規則（DRC）。
- 壅塞估測與全域繞線（global routing）。
- 時序（timing）、串音（crosstalk）與電源完整性。
- Rip-up and reroute、拆線重繞、協商式壅塞控制（negotiated congestion）。


## 6. 搜尋法綜合比較

| 搜尋法 | 主要資料結構 | 完備性 | 最佳性 | 時間複雜度 | 空間複雜度 | 適合問題 |
|---|---|---|---|---|---|---|
| **DFS** | 堆疊 / 遞迴 | 有限圖中完備 | 不保證最佳 | `O(V + E)` | `O(V)` | 迷宮、八皇后、回溯、拓撲排序 |
| **BFS** | 佇列 | 完備 | 無權圖中最佳 | `O(V + E)` | `O(V)` | 最少步數、過河問題、無權最短路 |
| **Dijkstra** | 優先佇列 | 非負權重圖中完備 | 最佳 | `O((V + E) log V)` | `O(V)` | 加權最短路、繞線成本最佳化 |
| **A*** | 優先佇列 | 啟發函數可採納時完備 | 啟發函數可採納時最佳 | 取決於啟發函數，最壞 `O(E log V)` | `O(V)` | 地圖尋路、NPC 追逐、遊戲 AI、繞線 |

### 如何選擇搜尋法？

- 只要求「找到一條路」且搜尋空間不大：可以使用 **DFS**，實作簡單。
- 要求「最少步數」且每步成本相同：使用 **BFS**。
- 每步成本不同，要求「最低總成本」：使用 **Dijkstra**。
- 每步成本不同，且能設計良好的啟發函數：使用 **A***，通常效率最好。
- 問題包含大量限制條件（如八皇后）：使用 **DFS + 回溯 + 剪枝**。

- 本範例的 IC 繞線採用「循序繞線」：先繞完的 net 會佔用格子，可能導致後面的 net 失敗。實務上會使用 rip-up and reroute 等技巧改善成功率。

### 可延伸的實驗

1. 將 `01_maze_dfs.py` 的 DFS 改成 BFS，比較找到的路徑長度是否更短。
2. 在 `03_eight_queens_dfs.py` 中測試 `N = 4, 6, 8, 10`，觀察解答數量與搜尋節點數的變化。
3. 在 `04_npc_astar.py` 中改用歐幾里得距離或加權曼哈頓距離作為啟發函數，觀察展開節點數的差異。
4. 在 `05_ic_routing.py` 中調整 net 的順序，觀察循序繞線的成功率如何受到順序影響。
5. 嘗試實作 **雙向 BFS（Bidirectional BFS）**、**IDA***、**Weighted A*** 或 **Rip-up and Reroute**，比較其效果。
