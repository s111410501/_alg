## 第 1 章：希爾伯特的問題

* 原文連結：[01-希爾伯特的問題.md](https://github.com/ccc115a/alg/blob/main/04-%E7%90%86%E8%AB%96/01-%E8%A8%88%E7%AE%97%E7%90%86%E8%AB%96/_book/01-%E5%B8%8C%E7%88%BE%E4%BC%AF%E7%89%B9%E7%9A%84%E5%95%8F%E9%A1%8C.md)

### 核心重點

1. **希爾伯特的 23 道問題（1900）**：大衛·希爾伯特（David Hilbert）在巴黎第二屆國際數學家大會發表《數學問題》演講，整理出 23 道待解問題。其中**第 2 題《算術公理之相容性》**直接推動了後來的數理邏輯與計算理論發展。
2. **自動定理證明的概念**：從歐幾里得《幾何原本》的公理系統與亞里斯多德三段式論出發，說明知識可以寫成一階邏輯規則。教材中以 Python 程式 `inference.py` 搭配 `test.kb`、`animal.kb`，實作前向推論與**肯定前件（Modus Ponens）**來自動推導結論。
3. **希爾伯特綱領（Hilbert Program，1920）**：希爾伯特希望為所有數學建立一套堅實的公理基礎，需滿足五大目標：
   * **形式化**：所有數學陳述都能寫成精確的形式語言。
   * **完備性**：所有為真的數學命題都能在系統內被證明。
   * **一致性**：系統內不會推導出彼此矛盾的命題。
   * **保守性**：透過理想工具證明出的實質結論，不依賴額外假設也能成立。
   * **確定性（可判定性）**：存在一套機械化演算法，能判定任何命題是否為定理。

## 第 2 章：哥德爾的定理

* 原文連結：[02-哥德爾的定理.md](https://github.com/ccc115a/alg/blob/main/04-%E7%90%86%E8%AB%96/01-%E8%A8%88%E7%AE%97%E7%90%86%E8%AB%96/_book/02-%E5%93%A5%E5%BE%B7%E7%88%BE%E7%9A%84%E5%AE%9A%E7%90%86.md)

### 核心重點

1. **羅素悖論與 ZFC 公理集合論**：康托爾的樸素集合論因「包含所有不包含自身的集合」而產生羅素悖論（常以理髮師悖論比喻）。為了消除矛盾，數學界改用一階邏輯重建 **ZFC 公理集合論**（包含外延、正規、分類、配對、並集、替代、無窮、冪集、良序、選擇共 10 條公理）。
2. **哥德爾完備定理（1929）**：哥德爾證明在純一階邏輯系統（例如單純的 ZFC）中，語意上的「真理」與語法上的「可證明性」是一致的——凡是為真的命題都能被推導出來。
3. **加入算術公理後的轉折（1931）**：當系統進一步納入描述自然數的**皮亞諾公理系統（Peano Axioms）**（共 5 條公理）後，系統就具備了表達整數算術的能力。
4. **哥德爾不完備定理**：
   * 哥德爾利用「哥德爾數」將數學符號與公式編碼為整數，在系統內部構造出可表達「某公式是否可被證明」的謂詞 `Provable(s)`。
   * 透過類似說謊者悖論的自我指涉結構（構造一個宣稱「我自己無法被證明」的命題），證明只要系統是一致的，就必然存在**既無法被證明、也無法被證偽的真命題**，且系統無法在內部證明自身的一致性。
   * 這直接宣告希爾伯特綱領追求「同時完備且一致」的目標無法實現。

## 第 3 章：丘奇的函數

* 原文連結：[03-丘奇的函數.md](https://github.com/ccc115a/alg/blob/main/04-%E7%90%86%E8%AB%96/01-%E8%A8%88%E7%AE%97%E7%90%86%E8%AB%96/_book/03-%E4%B8%98%E5%A5%87%E7%9A%84%E5%87%BD%E6%95%B8.md)

### 核心重點

1. **純函數計算模型（λ-Calculus）**：阿隆佐·丘奇（Alonzo Church）在 1930 年代提出 λ-Calculus，證明不需要硬體指令或變數賦值，僅靠「匿名函數的定義與代入」就能完成所有計算。
2. **用 Python `lambda` 從零建構計算系統**：
   * **邏輯系統**：定義 `TRUE`、`FALSE`、`IF`，並推導出 `NOT`、`AND`、`OR`、`XOR`。
   * **整數系統（Church Numerals）**：以函數套用的次數代表數字（`ZERO` 到 `FIVE`），實作 `INCREMENT`、`DECREMENT`、`ADD`、`SUBTRACT`、`MULTIPLY`、`POWER` 與 `IS_ZERO`。
   * **無具名遞迴（Y-Combinator / Z-Combinator）**：在函數沒有名稱的限制下，透過高階函數不動點組合子實現遞迴運算（如 `MOD`、`DIV`）。
   * **資料結構**：以函數實作 `PAIR`、`CONS`、`CAR`、`CDR`、`NIL`、`IS_NULL`、`RANGE`、`MAP`、`PUSH` 等串列操作。
3. **λ-Calculus 的不可判定性**：引用丘奇論文中的 Theorem XIX，指出**不存在通用演算法能判定兩個 λ-Calculus 表達式是否等價**。原因在於若運算過程不會停機，便無法判定兩者是否能透過 α-conversion（變數重新命名）與 β-reduction（函數代入展開）互相轉換。

## 第 4 章：圖靈的機器

* 原文連結：[04-圖靈的機器.md](https://github.com/ccc115a/alg/blob/main/04-%E7%90%86%E8%AB%96/01-%E8%A8%88%E7%AE%97%E7%90%86%E8%AB%96/_book/04-%E5%9C%96%E9%9D%88%E7%9A%84%E6%A9%9F%E5%99%A8.md)

### 核心重點

1. **從有限狀態機到圖靈機（1936）**：艾倫·圖靈（Alan Turing）為回應希爾伯特的可判定性問題，先從輸出依賴狀態與輸入的 Mealy machine、Moore machine 等有限狀態機出發（附 Python 實作），再加上「無限長紙帶」與「讀寫頭」，構成具備通用計算能力的**圖靈機（Turing Machine）**及 Python 模擬器。
2. **停機問題不可判定（Halting Problem）**：
   * **反證法構造**：假設存在一個能判斷任意程式是否會停機的函式 `isHalt(code, data)`。構造自我指涉程式 `U(x)`：當 `isHalt(x, x)` 回傳真（會停機）時，`U(x)` 故意進入無窮迴圈；當回傳假（不會停機）時，`U(x)` 立刻停機。
   * **產生矛盾**：將 `U` 自己作為輸入執行 `U(U)`，無論 `isHalt(U, U)` 判定結果為何都會與實際行為相反（邏輯與羅素悖論、韓非子《難一》「矛與盾」相同），因此 `isHalt` 不可能存在。
3. **實務直覺與理論對應**：教材以一個執行 $1000^4$ 步的程式為例，說明從外部觀察無法區分「跑得非常久」與「永遠不會停機」；這個不可判定結果與丘奇在 λ-Calculus 證明的函數等價性不可判定在精神上完全相通。

## 第 5 章：喬姆斯基的語法

* 原文連結：[05-喬姆斯基的語法.md](https://github.com/ccc115a/alg/blob/main/04-%E7%90%86%E8%AB%96/01-%E8%A8%88%E7%AE%97%E7%90%86%E8%AB%96/_book/05-%E5%96%AC%E5%A7%86%E6%96%AF%E5%9F%BA%E7%9A%84%E8%AA%9E%E6%B3%95.md)

### 核心重點

1. **生成語法（Generative Grammar）**：諾姆·喬姆斯基（Noam Chomsky）提出以有限的替換規則生成無限句子的形式語法。教材透過 Python（`grammar.py`、`gen.py`）示範如何依文法規則隨機生成英文句子。
2. **喬姆斯基階層（Chomsky Hierarchy）**：依文法規則的限制嚴格程度，由弱到強分為四層，各自對應一種抽象計算機器：

| 階層類型 | 語言名稱 | 特徵與教材範例 | 對應自動機 |
| :--- | :--- | :--- | :--- |
| **3 型** | 正規語言（Regular Language） | 規則最受限，可用正規表達式描述 | 有限狀態自動機 |
| **2 型** | 上下文無關語言（Context-Free） | 允許巢狀配對結構，如 $a^n b^n$（`anbn.py`） | 下推自動機（Pushdown Automaton） |
| **1 型** | 上下文相關語言（Context-Sensitive） | 需考量前後文長度與配對，如 $a^n b^n c^n$（`anbncn.py`） | 線性有界自動機（Linear Bounded Automaton） |
| **0 型** | 遞歸可枚舉語言（Recursively Enumerable） | 無額外規則限制，等同所有可計算問題 | 圖靈機（Turing Machine） |

3. **邱奇-圖靈猜想（Church-Turing Thesis）**：指出丘奇的 λ-Calculus 與圖靈機在計算能力上完全等價，代表所有直覺上「可由演算法計算」的問題都能由圖靈機完成。結合第 3、4 章的不可判定結果，也意味著存在電腦程式無法完全辨識的語言。

## 第 6 章：庫克的證明

* 原文連結：[06-庫克的證明.md](https://github.com/ccc115a/alg/blob/main/04-%E7%90%86%E8%AB%96/01-%E8%A8%88%E7%AE%97%E7%90%86%E8%AB%96/_book/06-%E5%BA%AB%E5%85%8B%E7%9A%84%E8%AD%89%E6%98%8E.md)

### 核心重點

1. **從「可不可算」到「算不算得完」**：前面章節處理「可計算性」，第 6 章轉向「計算複雜度」。史蒂芬·庫克（Stephen Cook）在 1971 年提出 **NP-Complete** 概念，奠定庫克-萊文定理（Cook-Levin Theorem）。
2. **核心複雜度類別與概念**：
   * **確定型 vs. 非確定型圖靈機**：確定型每一步只有唯一選擇；非確定型可視為能同時分岔探索所有可能路徑。
   * **P（Polynomial Time）**：確定型圖靈機可在多項式時間內「直接解出」的問題集合。
   * **NP（Nondeterministic Polynomial Time）**：非確定型圖靈機可在多項式時間內解出，或確定型圖靈機可在多項式時間內「驗證答案」的問題集合。
   * **多項式時間歸約（Reduction）**：若問題 A 可在多項式時間內轉換成問題 B，代表 B 至少和 A 一樣難。
   * **NP-Complete**：同時屬於 NP，且所有 NP 問題都能在多項式時間內歸約到它的問題。
3. **SAT 問題與庫克的編碼證明**：
   * **SAT（布林可滿足性問題）**：給定一條包含多個布林變數的邏輯式，判斷是否存在一組真假值指派使整條式子為真。教材以 `sat.py` 展示暴力窮舉會面臨 $2^n$ 的指數爆炸。
   * **證明思路**：庫克證明任何非確定型圖靈機在多項式時間內的整個計算歷程——包含每一步的**紙帶內容 $T_{i,j,k}$**、**讀寫頭位置 $H_{i,k}$**、**機器狀態 $Q_{q,k}$** 以及**狀態轉移規則**——都能被編碼成一條多項式規模的布林邏輯式。只要能快速解出這條 SAT 邏輯式，就等於解出原本的 NP 問題，藉此證明 SAT 是第一個 NP-Complete 問題。

## 延伸內容

### 延伸一：外觀不同、能力相同的計算模型

邱奇-圖靈猜想之所以被廣泛接受，關鍵在於許多彼此獨立的模型最後都被證明與圖靈機等價：

| 模型 | 提出者 | 核心操作 | 與圖靈機的關係 |
| :--- | :--- | :--- | :--- |
| $\mu$-遞歸函數 | Gödel / Kleene | 複合、原始遞迴、$\mu$-運算子（最小化搜尋） | 可互相模擬 |
| λ-Calculus | Church | 函數定義與 β-代入 | 第 3 章主角，等價 |
| 圖靈機 | Turing | 紙帶讀寫＋狀態轉移 | 第 4 章主角 |
| Post 系統 / 字串重寫 | Post | 依規則改寫符號串 | 等價 |
| 細胞自動機 | von Neumann | 格子依局部規則同步更新 | 等價（Life 遊戲可模擬圖靈機） |
| 寄存器機器 | Minsky | 計數器的增/減/零測試跳躍 | 等價 |

值得注意的是：**等價只發生在「可計算性」層次**。多帶圖靈機、非確定型圖靈機在「能不能算」上等價，但模擬時會付出平方甚至指數時間代價——這正是第 6 章 P 與 NP 分歧的起點。

### 延伸二：Rice 定理——不可判定性比停機問題更普遍

1953 年 Henry Rice 證明了一個統合性的結果：

> 對遞歸可枚舉語言的任何**非平凡語意性質** $P$，集合 $\{\langle M\rangle \mid L(M) \in P\}$ 都是不可判定的。

「非平凡」指有些機器滿足、有些不滿足；「語意」指性質只看 $M$ 接受的語言，不看程式碼長相。因此以下問題全部不可判定：

* $L(M)$ 是否為空？是否有限？是否包含某個特定字串？
* $L(M_1) = L(M_2)$ 是否成立？
* $L(M)$ 是否為正規語言？是否為上下文無關語言？

相反的，**語法性質**仍可判定，例如「$M$ 是否有 5 個狀態」「轉移表裡是否出現符號 1」。這條界線提醒我們：不可判定性來自「想從行為反推程式」，不是來自程式本身太複雜。

此外，停機問題與哥德爾第二不完備定理是一體兩面：若停機問題可判定，就能用演算法檢查「搜尋矛盾的程式是否會停機」，進而判定系統一致性，這與「系統無法在內部證明自身一致性」衝突。

### 延伸三：喬姆斯基階層的補充工具

Pumping Lemma（泵浦引理）是證明「某語言不屬於某層」的標準工具：正規語言與上下文無關語言都滿足特定的「可重複區段」性質，$a^n b^n c^n$ 正因違反此性質而不落入第 2 型，但仍屬於第 1 型。

階層間的封閉性與決定性差異也值得對照：

| 特性 | 正規 (Type 3) | 上下文無關 (Type 2) | 上下文相關 (Type 1) | 遞歸可枚舉 (Type 0) |
| :--- | :--- | :--- | :--- | :--- |
| 聯集 / 串接 / Kleene * | 封閉 | 封閉 | 封閉 | 封閉 |
| 交集 | 封閉 | **不封閉** | 封閉 | 封閉 |
| 補集 | 封閉 | **不封閉** | 封閉 | 不封閉 |
| 成員問題 $w \in L$ | 可判定 | 可判定（CYK，$O(n^3)$） | 可判定（PSPACE-complete） | 僅半可判定 |
| 等價問題 $L_1 = L_2$ | 可判定 | **不可判定** | 不可判定 | 不可判定 |

### 延伸四：從 Cook-Levin 到 Karp 的 NP-Complete 版圖

庫克 1971 年證明 SAT 是 NP-Complete；隔年 Richard Karp 接著證明 21 個經典問題（3SAT、CLIQUE、VERTEX COVER、HAMILTONIAN CIRCUIT、KNAPSACK 等）同樣是 NP-Complete，從此建立標準的歸約鏈：

```
SAT → 3SAT → CLIQUE → VERTEX COVER → HAMILTONIAN CIRCUIT → TSP
```

複雜度類之間形成清楚的包含關係：

$$P \subseteq NP \subseteq PSPACE \subseteq EXPTIME$$

其中 $P \neq EXPTIME$ 已由時間階層定理證明為嚴格包含，因此上述鏈中**至少有一處是嚴格的**，但不知道是哪一處——這正是 P vs NP 至今未解的原因。

實務上另有個有趣的反差：基於 DPLL / CDCL 的 SAT solver 在工業規模實例上往往跑得很快，廣泛用於晶片驗證與形式驗證。這印證了「最壞情況指數難」不代表「每個實例都難」，也是複雜度理論與工程實務之間最常被提到的落差。
